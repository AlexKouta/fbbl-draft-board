# Decisions

Choices made while building, where the PRD was silent or left room. Dates are Melbourne time.

## Data (10 October 2026)

- **Fetch script in Node** (`scripts/fetch_data.mjs`), standard library only. The header shape from the PRD worked unchanged on the first call: `limit: 1500` returned all 1,095 active players in one request, so no paging was needed. Paging with `offset` is implemented anyway in case ESPN caps the limit later.
- **Raw response saved** to `data/raw/players_raw.json` (git-ignored). `--offline` re-runs the transform from it.
- **Pool is 246 players**, slightly above the PRD's 220 to 240 estimate, because the top-200-by-projection and top-200-by-last-season sets overlap less than expected (rookies and returning players). Left as is; no manual include list entries yet.
- **Validation passed exactly** on the first run (no tolerance was needed on the projection row).
- **Age was fetched** from `sports.core.api.espn.com/v2/sports/basketball/leagues/nba/athletes/{id}`. It returns `age` directly. All 246 pool players resolved, 4 requests at a time with a short pause. Results are cached in `data/raw/ages.json` so re-running the fetch does not repeat the 246 calls. `--no-ages` skips the step.
- **Tier seeding** found the largest gap within ±3 of each target. Result: S 5, A 8, B 14, C 21, D 31, E 41, F 126. The A cut moved to 13 and the B cut to 27 because those gaps (0.7 and 0.1 fppg) were the largest in their windows; the tail of the pool is flat, so most cuts are close to the targets.
- **3PM is stored** per source even though it is not scored, so the player sheet can show it.
- **FG% and FT%** are computed from makes and attempts rather than read from ESPN's stat 19 and 20, so they always agree with the totals shown.

## App

- **Repository layout:** the app lives at the repository root (not a `docs/` or `app/` folder) so GitHub Pages serves it with no configuration and `data/players.json` matches the PRD path.
- **Reference files** are copied into `reference/`. The originals at the project root are git-ignored so they are not committed twice.
- **Service worker** applies the network-first, 3 second timeout, cache fallback strategy to every same-origin GET, not only `index.html` and `players.json`. Reason: app updates (CSS and JavaScript) should arrive the same way data updates do, and this keeps the worker simple. Bump `VERSION` in `sw.js` when shipping an update that must invalidate the old cache.
- **Tapping an available row in Draft mode** (anywhere except the name) opens the draft modal, the same as the Draft button. The modal is the confirmation, so this is not a destructive single tap. Tapping the name opens the read-only player sheet. Tapping a drafted row opens the correction modal.
- **Tier chip in Draft mode** does nothing special; tiers are locked, and the row tap rules above apply.
- **Status filter on mode change:** switching to Draft sets the status filter to Available and switching to Prep sets it to All, as the PRD's mode defaults. Clear filters keeps the current mode's default status.
- **Search clears after a pick** as the PRD asks. Other filters are kept.
- **Rank column** is the position in the full pool under the current sort and stat source, and is not sortable itself. Players with no games in the selected source show a dash and sort last for stat columns.
- **Group by tier** header rows count availability across the whole pool for that tier, not only the filtered rows, so "8 of 8 available" is meaningful under any filter.
- **Target cue** uses the player's target pick versus Alex's next pick number. Without a draft slot there is no cue.
- **Lineup grid** uses a maximum bipartite matching over the 10 starter slots (so as many starters as possible are placed), trying each player's most restricted slots first; leftovers go to the bench in projected FPPG order. More than 13 players shows an "over the roster limit" note rather than hiding anyone.
- **Teams and rounds are editable** in Settings per the PRD, clamped to sensible ranges. Changing teams below the current slot clears the slot.
- **Export** writes pretty-printed JSON (one-space indent) so it is readable in the text box, plus a file download named with the timestamp.
- **Pick reordering (Nice)** is implemented as up and down arrows in the Picks view.
- **Wake lock (Nice)** is requested in Draft mode and re-requested when the app returns to the foreground. Safari on iPad supports it from iOS 16.4; it silently does nothing where unsupported.
- **Theme** follows the device setting. Tier colours are seven distinct hues with separate light and dark values.
- **Icons** are generated by `scripts/make_icons.mjs` (a basketball on a dark square) with no image libraries.
- **No analytics, fonts, or CDN assets.** Every asset is served from the repository.

## Testing

- `tests/run_tests.mjs` covers the automated criteria in the PRD and runs with no dependencies.
- `tests/browser_checks.mjs` covers the browser criteria at 1180×820 and 820×1180 in headless Chromium. It needs Playwright, which was available from the npm cache on the Mac (pointed at via `PLAYWRIGHT_MODULE` and `CHROME_PATH`). Playwright's offline emulation was also cross-checked by killing the local server before a reload; the app still loaded with all 246 rows from the cache.

## Skipped

- Nothing in the Must list was skipped. All three Nice items (age, wake lock, pick reordering) were done.
